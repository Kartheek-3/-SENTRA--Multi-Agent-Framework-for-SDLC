# SEAM Canonical Documentation & File Structure Map

## Executive Purpose

This document establishes the **single authoritative source of truth** for every file and document category within the SEAM repository. It defines clear boundaries between application source code, module documentation, validation evidence, research analyses, and final academic submission deliverables, eliminating the redundancy and ambiguity identified during the repository audit.

## 3. Handling Legitimate Same-Name Files

Several files share identical baselines across the repository but serve **distinct, legitimate roles**:

1. **`package.json`**:
   - `seam-ide/package.json`: Manages the React/Vite development server, frontend dependencies, and build scripts.
   - `seam-ide/src-tauri/package.json`: Manages the desktop packaging metadata.
   - `generated_projects/*/package.json`: Project manifests generated by the Coding Agent for target user applications.
   - *Status*: **D5 (Legitimate Same-Name)**. Must remain separate.

2. **`tsconfig.json`**:
   - `seam-ide/tsconfig.json`: Root TypeScript configuration for the IDE client.
   - `seam-ide/tsconfig.node.json`: Configuration for Vite configuration scripts.
   - *Status*: **D5 (Legitimate Same-Name)**. Standard Vite configuration pattern.

3. **`requirements.txt`**:
   - `SEAM/requirements.txt`: Authoritative dependency list for SEAM's FastAPI backend and AI agents.
   - `generated_projects/*/requirements.txt`: Dependencies generated for output user applications.
   - *Status*: **D5 (Legitimate Same-Name)**. Must remain separate.

4. **Phase Validation Summaries vs Root Reports**:
   - Root `DIAGRAM_ENGINE_PHASE1_VALIDATION.md` (10KB) is the complete validation report.
   - `SEAM/DIAGRAM_ENGINE_VALIDATION.md` (1KB) is an obsolete early stub mentioning `qwen3:4b`.
   - *Status*: **D3 (Outdated Version)**. The root report is canonical; the `SEAM/` stub should be archived or removed.

## 4. Dual `generated_projects/` Anomaly Resolution

The repository currently exhibits two generation roots:
- `c:/Users/Windows 11/Downloads/SEAM1/generated_projects/`
- `c:/Users/Windows 11/Downloads/SEAM1/SEAM/generated_projects/`

### Root Cause
When backend tests were run from the monorepo root (`python -m pytest SEAM/tests`), the relative output path `generated_projects/` was resolved relative to the current working directory (`SEAM1/`). When tests were run from inside `SEAM/` (`cd SEAM; pytest`), outputs were created under `SEAM1/SEAM/generated_projects/`.

### Canonical Decision
- **Authoritative Directory**: `c:/Users/Windows 11/Downloads/SEAM1/generated_projects/` (or configured via environment variable `SEAM_PROJECTS_DIR`).
- **Resolution**: Update backend configuration to dynamically resolve `generated_projects/` relative to the repository root or backend root consistently, and consolidate existing generated artifacts into the primary folder.
